# راهنمای نصب و راه‌اندازی فروشگاه

این بسته، سایت پورتفولیوی قبلی رو بدون حذف هیچ‌چیز به فروشگاه محصولات دیجیتال تبدیل می‌کنه
(قالب سایت، افزونه وردپرس، اتوماسیون، مدل هوش مصنوعی، اپلیکیشن، دوره آموزشی).
معماری همون قبلیه: **PHP 8 خام + MySQL، بدون فریم‌ورک**، فرانت HTML/CSS/JS ساده.

> سایت روی **Vercel** اجرا نمی‌شه (PHP/MySQL لازم داره). همون هاست PHP که پنل مدیریتت روش کار می‌کنه
> (دامنه‌ی اصلی `abjadian.ir`) محل درست نصبه.

---

## ۱) نصب (۵ مرحله)

1. **بک‌آپ** بگیر: دیتابیس + فایل‌های سایت.
2. فایل‌های این بسته رو روی هاست آپلود کن (روی فایل‌های قبلی). **`includes/config.php` خودت رو نگه دار** —
   در این بسته هیچ تغییری روش نداده‌ایم؛ تنظیمات فروشگاه در فایل جدا (`includes/store-config.php`) هستن.
3. **دیتابیس رو به‌روزرسانی کن** (فقط جدول‌های جدید `shop_*` و تنظیمات پیش‌فرض اضافه می‌شن؛ هیچ داده‌ی قبلی تغییر نمی‌کنه):
   - یا از پنل: **مدیریت → فروشگاه → داشبورد فروشگاه** (اگه جدول‌ها نصب نباشن خودش می‌بردت به صفحه‌ی «به‌روزرسانی دیتابیس») و دکمه‌ی اجرا.
   - یا با خط فرمان: `php database/migrate.php`
   - نصب کاملاً تازه: اول `database.sql` رو ایمپورت کن، بعد یکی از دو روش بالا.
4. دسترسی نوشتن بده: `uploads/` (تصاویر محصولات) و `storage/` (فایل‌های خصوصی + کلید رمزنگاری).
5. در **پنل → فروشگاه → تنظیمات فروشگاه**، بخش «وضعیت سیستم» رو ببین؛ هر چی «نیاز به توجه» بود رو درست کن.

اجرای مجدد مایگریشن بی‌خطره (هر فایل فقط یک‌بار اعمال می‌شه).

### کلید رمزنگاری لایسنس‌ها
کدهای لایسنس رمزنگاری‌شده (libsodium) ذخیره می‌شن. کلید به‌صورت خودکار در `storage/app.key` ساخته می‌شه.
**از این فایل پشتیبان بگیر** — بدون اون، لایسنس‌های ذخیره‌شده قابل خوندن نیستن.
(یا کلید ۶۴ حرفی hex رو در `STORE_APP_KEY` بذار.)

### فایل‌های خصوصی (ZIP/RAR)
پیش‌فرض: `storage/` داخل پروژه، با `.htaccess` که دسترسی مستقیم رو کامل می‌بنده (فقط از طریق `download.php` سرو می‌شن).
امن‌تر: در `includes/store-config.php` مقدار `STORE_PRIVATE_PATH` رو بذار روی مسیری **بیرون از public_html**.

### محدودیت آپلود
برای فایل‌های بزرگ باید در `php.ini` یا `.user.ini` مقدار `upload_max_filesize` و `post_max_size` رو بالا ببری
(پنل در «وضعیت سیستم» مقدار فعلی رو نشون می‌ده).

## ۲) اتصال درگاه پرداخت — تنها کاری که باید خودت بکنی

همه‌چیز دیگه (ساخت سفارش، انتقال به درگاه، بازگشت، **تأیید سروربه‌سرور**، جلوگیری از پرداخت تکراری، تحویل فایل/لایسنس،
صفحات موفق/ناموفق، گزارش مالی) آماده‌ست و فقط از طریق یک رابط کوچک (سه متد اصلی: request ، parseCallback ، verify) با درگاه حرف می‌زنه.
تا درگاه وصل نکنی، **هیچ پرداخت جعلی/آزمایشی در سایت وجود نداره**: سفارش ثبت می‌شه و پیام «درگاه راه‌اندازی نشده» نشون می‌ده.

### گزینه A — زرین‌پال (درایور آماده)
در `includes/store-config.php`:
```php
define('STORE_GATEWAY', 'zarinpal');
define('STORE_GATEWAY_MERCHANT_ID', 'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx');
```
آدرس بازگشت (Callback) خودکار ساخته می‌شه: `https://abjadian.ir/payment/callback/zarinpal`.
> درایور مطابق مستندات رسمی نسخه‌ی ۴ زرین‌پال نوشته و با یک سرور ساختگی همان API تست شده، **ولی روی سرور واقعی زرین‌پال از اینجا تست نشده**.
> قبل از اعلام عمومی یک پرداخت واقعی کم‌مبلغ (یا `STORE_GATEWAY_SANDBOX = true`) انجام بده.

### گزینه B — درگاه دیگر
فایل `includes/gateways/CustomGateway.php` رو باز کن؛ ۳ متد (`request`, `parseCallback`, `verify`) با کامنت و نمونه‌ی کد آماده‌ست.
`$implemented = true` رو بذار و در `store-config.php`: `STORE_GATEWAY = 'custom'` + شناسه‌ی پذیرنده.
> اگه درگاهت با **فرم POST** منتقل می‌کنه (نه لینک)، آدرسش رو به `form-action` در CSP فایل `.htaccess` اضافه کن
> (الان `form-action 'self'`). درگاه‌های تحت‌لینک مثل زرین‌پال نیازی ندارن.

### قواعد امنیتی پرداخت (در کد اعمال شده)
- فقط جواب **verify سروربه‌سرور** پرداخت رو «موفق» می‌کنه؛ برگشتن مرورگر به آدرس موفقیت هیچ ارزشی نداره.
- تأیید زیر قفل ردیف دیتابیس انجام می‌شه → کال‌بک تکراری/همزمان، دوبار تحویل یا دوبار شمارش فروش نمی‌سازه.
- مبلغ تأییدشده باید با مبلغ سفارش (که روی سرور محاسبه شده) برابر باشه، وگرنه رد می‌شه.
- شناسه‌ی تراکنش بانکی تکراری رد می‌شه.
- جواب نامشخص (timeout) هرگز «ناموفق» ثبت نمی‌شه؛ `verifying` می‌مونه و بعداً بررسی می‌شه.
- اگه پرداخت تأیید بشه ولی تحویل مشکل داشته باشه، پرداخت پاک نمی‌شه؛ سفارش «خطای تحویل» می‌گیره و از پنل «تلاش مجدد» داره.

## ۳) Cron (توصیه‌شده)
```
*/5  * * * * php /مسیر/سایت/cron/verify-pending-payments.php
*/10 * * * * php /مسیر/سایت/cron/release-reservations.php
```
اولی پرداخت‌های «تأیید نامشخص» رو دوباره از درگاه می‌پرسه؛ دومی رزرو لایسنس سفارش‌های پرداخت‌نشده‌ی منقضی رو آزاد می‌کنه
(بدون cron هم رزروها هنگام ثبت سفارش جدید و باز شدن داشبورد فروشگاه آزاد می‌شن).

## ۴) کار با پنل

| بخش | کار |
|---|---|
| **محصولات** | افزودن/ویرایش/فعال‌وغیرفعال/انتشار/کپی/سطل زباله؛ ۸ تب: اطلاعات، قیمت، توضیحات، مشخصات و FAQ، تصاویر، فایل‌ها، لایسنس، سئو |
| **دسته‌بندی** | شش دسته‌ی اولیه ساخته شده؛ افزودن/ویرایش/حذف (با انتقال محصولات)، سئوی مستقل هر دسته |
| **سفارش‌ها** | فیلتر/جستجو/CSV، جزئیات پرداخت‌ها، تلاش مجدد تحویل، استعلام مجدد از درگاه، لغو، تأیید دستی پرداخت، بازپرداخت (دلیل الزامی + لاگ) |
| **نظرات** | صف تأیید؛ تأیید/رد/حذف/ویرایش، عملیات گروهی؛ فقط نظر تأییدشده نمایش داده و در امتیاز حساب می‌شه |
| **لایسنس‌ها** | افزودن تکی/گروهی، موجودی، غیرفعال‌کردن، جایگزینی لایسنس تحویل‌شده، نمایش کد (فقط owner، در لاگ ثبت می‌شه) |
| **گزارش فروش** | بازه‌ی دلخواه، روزانه/هفتگی/ماهانه، فروش به تفکیک دسته/محصول، CSV |
| **تنظیمات** | واحد پول، تعداد در صفحه، مدت رزرو، اعتبار لینک دانلود، سقف دانلود، نظرات، وضعیت سیستم |

**نقش‌ها:** `owner` همه‌چیز؛ `editor` محصول/دسته/نظر/افزودن لایسنس و مشاهده‌ی سفارش را دارد ولی
بازپرداخت، تأیید دستی پرداخت، نمایش کد لایسنس، گزارش مالی، CSV سفارش‌ها و تنظیمات را ندارد.

**درآمد** در همه‌جا یعنی مجموع سفارش‌های **پرداخت‌شده** (بازپرداخت‌شده‌ها حساب نمی‌شن).

### نکات محصول
- تحویل «فایل» و «تحویل دستی» همیشه تعداد ۱؛ «لایسنس / فایل+لایسنس» تا سقف تعیین‌شده چند عدد.
- محصول فایل‌دار بدون فایل فعال، و محصول لایسنس‌دار بدون لایسنس آزاد، **قابل خرید نیست** (تا پولی گرفته نشه که تحویلش ممکن نیست).
- برای انتشار، «کلمه‌ی کلیدی» و «توضیح متا» الزامیه.
- تغییر slug یک ریدایرکت ۳۰۱ از آدرس قبلی می‌سازه. حذف دائمی فقط برای محصولی که هیچ سابقه‌ی سفارشی نداره.
- تصاویر بعد از آپلود به WebP و سه اندازه (بزرگ/کارت/بندانگشتی) تبدیل می‌شن.
- پیش‌نمایش پیش‌نویس: لینک امضاشده‌ی «پیش‌نمایش صفحه‌ی محصول» در صفحه‌ی ویرایش.

## ۵) مسیرها
`/shop` · `/shop/category/{slug}` · `/shop/{slug}` · `/cart` · `/checkout` · `/payment/start|success|failed/{order}` ·
`/payment/callback/{gateway}` · `/dashboard/purchases` · `/dashboard/orders[/{order}]` · `/dashboard/reviews` · `/download/{e}/{f}`.
`sitemap.xml` شامل دسته‌ها و محصولات منتشرشده‌ست؛ `robots.txt` سبد/پرداخت/دانلود را می‌بنده.

> در بسته‌ی قبلی `robots.txt` به `sitemap.xml` اشاره می‌کرد ولی قانونی برای آن در `.htaccess` نبود (۴۰۴ می‌داد)؛ اضافه شد.

## ۶) تست‌ها (روی دیتابیس **آزمایشی** اجرا کن، نه سایت زنده)
```
STORE_ALLOW_TESTS=1 php tests/run.php          # ۱۰۱ تست منطق: قیمت، سبد، سفارش، پرداخت، تحویل، لایسنس، نظرات، آپلود…
STORE_ALLOW_TESTS=1 php tests/seed-http.php    # داده‌ی دمو + کاربر/ادمین آزمایشی
python3 tests/http_flow.py                     # ۷۱ تست HTTP مسیر خریدار روی Apache واقعی
python3 tests/http_admin.py                    # ۸۵ تست HTTP پنل مدیریت
```
تست‌های HTTP نیاز به یک نمونه‌ی در حال اجرا (`BASE=http://localhost:8080`) و درایور آزمایشی دارن؛ درایور آزمایشی فقط در پوشه‌ی
`tests/` هست و تنها وقتی لود می‌شه که خود پروسه با متغیر محیطی `STORE_TEST_MODE=1` اجرا شده باشه (از طریق config قابل فعال‌سازی نیست).
پوشه‌های `tests/ database/ storage/ cron/` با `.htaccess` از وب بسته‌ان.
